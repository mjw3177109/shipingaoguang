# V0.3 极小规模真实人工球框实验

本文件描述一个真正可执行的**真实视频、人工目视审查四个球框**的实验，不是可商用模型的质量验收。

## 训练数据

两段来源明确的 Wikimedia Commons 视频，均为 1280×720：
- `Basketpass.webm`：Benoît Prieur，CC0 1.0；人工目视定位 1.0s、2.0s 的篮球。
- `VCB FCB(4).webm`：Coentor，CC BY-SA 3.0；人工目视定位 3.5s、4.0s 的篮球。

人工定位数据：`benchmarks/real_ball_boxes_pilot.json`。篮球框为原视频像素坐标（左上 x1,y1 和右下 x2,y2）。这些框来自选定的真实画面，仅四帧，不保证像素级完美，也**不是整段录像的完整标注**。没有为其余未检查画面虚构“本帧无球”负标签。

GitHub Actions 在运行时下载源片段，提取对应帧，并按**比赛来源**分开：传球视频训练、罚球视频验证。采用 Torchvision 预训练 MobileNet320 Faster R-CNN，并替换检测头为“背景 / 篮球”，CPU 上至少执行真正的权重更新，产生 checkpoint。随后在真实罚球视频上使用这个 checkpoint 做 CPU 推理，输出待审候选 JSON。

本试验不是对实际篮球馆分布的公平估计。仅 2 张 train 正例、2 张 val 正例、0 负样本；数据太少，准确率很可能极差。测试报告的 Precision/Recall 数字只能用于确认代码执行，不得对外宣称真实投篮召回率或可商用。

## 测试查看方式

GitHub Actions -> `Real Human Box Tiny CPU Specialist Trial`，对应 Artifacts 包含 train report 与 infer proposals JSON。流程成功只表示训练、保存、装载、检测、回传结构能够运行。

## 下一阶段最低数据目标

实战阶段至少 10 场不同角度/光照的已获授权比赛，每场选取多段有球和无球的视频片段，建立 500~2000 张人工审核框（实际数量需按误检/漏检曲线调整）。按整场比赛划分 train/val/test，**不把同场邻接帧随机拆散**。

优先解决的实际问题是远景小球、蓝黑灯光、橙色球衣、篮筐干扰以及球被遮挡；完成真值才开始承诺检测性能。

该数据**毫无商业统计意义**：四帧极少，2 张验证图且无难负样本。355 检测框是模型误报倾向的证据，不是成功率。根据这次实测，**此 checkpoint 不得进入生产**，只能供研发排障。下一版将以人工标注数量、跨比赛泛化和低误报率为门槛。

训练得到的 checkpoint 默认附带 `research_only=true`，推理程序会拒绝自动加载此类未审核权重；仅研究命令显式提供 `--allow-research-checkpoint` 可绕过。正式模型升级须经独立的人审与线上授权流程。
