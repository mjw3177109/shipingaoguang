# V0.2 实战评测与性能优化指南

> 当前版：人工标注投篮尝试 → Kaggle/本地 GPU 分析篮筐附近篮球 → 独立评测 → 参数优化 → 留出集复测。**不是投篮命中、盖帽或助攻识别**。

## 1. 先准备数据，禁止未经授权公开上传

建议先收集至少 10 场已获授权、固定机位、光照不同的 1080P 篮球比赛。将比赛按场次拆为 **开发集（约 6 场）** 与 **完全独立留出集（约 4 场）**。不要在留出集上反复调参，避免虚高的性能指标。为保护球员隐私，Kaggle 视频及 JSON 应使用私有 Dataset。

## 2. 人工建立真实投篮尝试标签（Ground Truth）

登录 Django 工作台 → 上传比赛 → 打开比赛详情 → 播放并检查整段视频。

在新增的“实测标注”面板中，暂停至投篮出手时刻，点 **取当前视频时间**，再点 **标记投篮尝试**。投中、投丢都必须标记，篮板/普通运球不能代替出手。独立审核人应尽量不参考自动候选，防止标签偏见。

认真检查整场后，点击 **确认全场标注完整**，下载 `game-ID-truth.json`。新增/删除任何标签都会自动撤销“标注完整”状态，须重新确认。即使全场没有投篮，也需明确标注完整并导出 0 事件文件。

评估要求 `complete_within_scope=true`。没有确认完整的文件会被拒绝，不能谎称召回率。

## 3. 使用 Kaggle 免费 GPU 试验

- Notebook: [`notebooks/kaggle_shot_candidates_v02.ipynb`](../notebooks/kaggle_shot_candidates_v02.ipynb)
- 设置 **Accelerator = GPU**，分别配置 `VIDEO_PATH`、`CONFIG_PATH` 与 `TRUTH_PATH`。先在 Web 工作台框选篮球筐、保存，下载对应的 GPU 配置。
- 默认模型 `mobile320`（速度优先、不能保证召回率）。需要对比精度时试 `resnet50`，分别记录耗时与准确率。
- Notebook 默认每 1.5 秒抽帧、最多 1800 帧，意味着超过约 45 分钟可能被截断。输出 `incomplete_scan=true` 时**不能用它宣称全场召回率**。
- GPU 第一次运行可能需要互联网下载权重；受 Kaggle 当前权限、显卡配额及模型许可限制。
- Notebook 产出：`candidates.json`（待审候选）、`ball_observations.json`（原始位置采样）、`evaluation/report.md`（可选客观评测）。

## 4. 命令行评测（不用 GPU）

```bash
python -m highlights.vision.evaluate \
  --proposals candidates.json \
  --truth game-1-truth.json \
  --out reports/game-1 \
  --gpu-hourly-usd 0.59
```

输出 `evaluation.json` 和 `report.md`，重点观察：

| 指标 | 解释 |
|---|---|
| Recall | 所有人工投篮尝试中，落入**一对一匹配**候选的比例 |
| Precision | 候选片段中，匹配到独立投篮标签的比例 |
| FP / 10 min | 每 10 分钟画面对应的未匹配候选数，反映人工审核负担 |
| Raw event coverage | 投篮时间点被至少一条候选覆盖的比例（但一个超长候选可覆盖多个投篮，不等于一对一召回率） |
| Compute | 模型实际扫描耗时及按输入 GPU 价估算的纯算力费用 |

一段集锦可能包含多个投篮，本评测用**一对一**匹配，避免一条长集锦被算成多次“正确检测”。这个指标适合研究自动分片质量，但与传统动作分类准确率不同。

## 5. 复用一次 GPU 扫描，在 CPU 上调参

```bash
python -m highlights.vision.tune \
  --observations ball_observations.json \
  --truth game-1-truth.json \
  --out tuning/game-1 \
  --min-hits 1,2,3 \
  --confidence 0.2,0.35,0.5
```

搜索输出 `tuning.json` 和 `best_proposals.json`。参数控制篮筐附近连续出现篮球的最低采样次数和检测置信度；它们**不**表示进球概率。

**务必用新比赛做留出集测试**，调参过程中的 F1 只是开发集成绩。若想对比小球检测能力，另跑 `--model resnet50`，这是一个新的 GPU 模型实验，会额外消耗 GPU 额度。

## 6. 多场独立汇总

新建一个 `manifest.json`，其中数组 `games` 每项有唯一 `id`、`proposals` 和 `truth` 路径（相对于 manifest 文件所在目录）。示例见 `benchmarks/example_manifest.json`。

```bash
python -m highlights.vision.batch \
  --manifest benchmarks/example_manifest.json \
  --out reports/synthetic-example
```

汇总输出 micro Precision / Recall / F1、每10分钟误报数、全片覆盖场次，以及估算 GPU 总费用。**benchmarks/example_* 全部是模拟数据，用来跑测试，不代表真实篮球识别准确率。**

## 7. 验收门槛与风险

部署前请用留出集报告判断是否达到以下*建议门槛*：投篮尝试候选召回率至少 70%，每10分钟误报尽量少于 3 段，审核人节省时间达到 50%（分别人工记录）。这些是业务目标，当前**尚无真实数据证明达到**。

此版本依旧需要人工篮筐标定、标注及候选审核；Kaggle 不是无人值守的生产 API。开源检测模型和权重需审查许可证，未授权比赛视频不可公开上传。
