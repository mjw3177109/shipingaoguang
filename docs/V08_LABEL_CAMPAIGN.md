# BasketCut V0.8 — 跨比赛标注计划与持续 CPU 分轮采集

本阶段**不声称自动识别进球准确率提高**，而是解决 V0.7 的数据瓶颈：单场只有24条 CPU 时间建议，重复抽帧总返回相同时间点且覆盖旧建议，缺少多场标注进度与难负样本缺口管理。

## 这次实现

1. **多比赛数据采集看板**：球馆首页→“V0.8 数据采集看板”，只汇总当前登录账号拥有的比赛。统计人工篮球正例、人工明确无球负例、完成复核、待复核、已授权比赛及 CPU 待标注时间点。单场与全局入口直达人工标注。
2. **建议缺口**：首轮数值目标为至少8场完成授权与复核的比赛、至少120个篮球正例、40个明确无球负例。未满足条件会逐条列出原因。达到数值不代表模型已经通过测试，也不等于可以商用。
3. **可持续 CPU 多轮抽帧**：每次点击“再抽一轮”会使用不同时间网格；每轮最多从实际录像取96帧，产生最多24个**时间建议**，不自动判有球或无球。保留上一轮未处理时间点，已标注以及相近重复点排除，最大累积300条待审。标注后对应时间点自动移除，按需增加新一轮。
4. **安全预览**：球框标注页显示最多6张“待检查真实视频帧”缩略图。它们通过原有需要登录且校验所属球馆权限的临时 JPEG 接口提取，不公开上传、也不会变成训练标签。
5. **机器可读进度**：`/ball-campaign/report.json` 只暴露当前用户的统计和游戏标题，禁止公共访问；可用于日后连接标注团队看板。
6. **保留原来系统**：V0.1–V0.7 的音频/颜色辅助高光、研究模型导入、人工审核与 MP4 导出、二次复核、训练导出和模型发布拦截保持不变。

## 操作

```powershell
git checkout main
git pull origin main
docker compose up -d --build
```

Web 入口：

- 首页点击“V0.8 多场比赛训练样本采集”→查看每场已标注、待审与负样本缺口。
- 点击某场“继续标注”→“再抽一轮 CPU”，使用 Worker 队列分析→点击待审图片跳到指定秒数，人工标篮球框或勾选无球并选择球衣/地板/广告等难负样本原因→逐帧二次复核→确认训练权利依据。
- 每轮自动获得不同时间分布；即使模型误检，也只能算待人审时间点。

数据库迁移：`0009_ball_sampling_round.py` 为现有比赛新增从0开始的轮次字段；旧标签和已有待审建议不修改、不删除。

## 真实视频检验

工作流 `v08-cpu-multiround.yml` 在 GitHub Actions 上下载 Wikimedia Commons 的 `Basketpass.webm`（Benoît Prieur，CC0 1.0）和 `VCB FCB(4).webm`（Coentor，CC BY-SA 3.0）两段真实篮球视频，分别执行 CPU round0 与 round1，验证得到的**候选时间点不同**、输出全部是纯建议、不含篮球/无球标签。Artifact 只有元数据 JSON，不含第三方视频、原帧或未通过验收的权重。许可归原作者，使用请核对署名/ShareAlike 等要求。

## 实际数据不足的事实

此前只有两段公开片段中4帧人工目视定位过篮球，缺少明确无球负样本；更新采样代码并没有自动新增人工标签或生成合格训练集。开始重新训练前，应优先在多个不同机位、光照和球衣颜色的**已授权**比赛中建立足量有球/无球人工标注并复核，再用 V0.7 `--three-way --verified-only` 导出。V0.5 的独立测试指标必须从新模型、真实标签计算，而不能凭空设定提升率。

GitHub Actions 普通 CPU 是开发 CI，免费分钟可能受账户额度及使用规则限制，不应作为收费无人值守生产服务。
