# BasketCut V1.0 — 人工审核高光剪辑可用版（CPU 优先）

## 产品范围

**已经实现可用流程**：上传自己有权处理的比赛视频 → 免费 CPU 视觉/声音辅助候选或人工加片段 → 人工逐条复核、调整时间/标注球员 → 冻结审核片段清单 → 后台 FFmpeg 720p/30fps MP4（可选原声或无声）输出 → 账号权限内下载。

**没有声称完成**：全自动识别得分、某球员身份、投篮命中判定、无需人工的全自动篮球馆生产、正式云端部署或高精度训练模型。V0.9 的研究模型仍因真实标注太少而处于 `research_only` 状态。

## V1.0 新增可靠性功能

1. **不可变导出快照**：点击生成集锦会即时固定当时真正人工通过的候选 ID、起止时间、球员标记与来源；快照含原始录像首尾指纹、时长、片段合计时长和 SHA256。
2. **避免排队漂移**：后台出片前重新确认该录像未被替换，原快照没被改变，所有片段仍存在、仍人工通过且时间/球员一致。若被修改或撤销审核，任务失败并提示重新创建，而不是静默输出错误剪辑。
3. **重复提交保护**：同一比赛同一球员的相同快照处于 queued/running 时，不会因连续点击产生重复队列任务。
4. **取消与失败重试**：可以取消未开始的排队任务；已失败的 V1.0 快照可重新创建追溯的重试任务，单链路最多 3 次，不能继续对失效审核数据重试。正在渲染的 FFmpeg 任务不能直接取消/并发强制杀死。
5. **审计和进度**：每处理完一段，显示“已处理几段 / 总段数”，单任务最多 150 段、累计时长最多 30 分钟、单段不超过 120 秒。提供私有 `edit-list.json`，可检查比赛 ID、审核清单、重试链路和 SHA256。
6. **历史兼容**：升级前已经排队的任务仍可按原有规则处理，但其编辑清单会注明 `legacy_export=true`，不冒充可追溯快照。
7. **隐私**：编辑清单和出片必须登录，并验证球馆账号所有权。源视频和私有图片不公开部署或存储到公共 GitHub。

视频输出为 H.264 720p 30fps，支持按任务选择 **保留原始现场声音 AAC 48kHz** 或 **无声**。若来源视频本来没有音轨，选择“保留原声”会生成静音音轨，以保证拼接格式一致。转码过程中只按审核的开始/结束帧剪辑，没有增加特效、音乐或者 AI 发明镜头。短视频平台竖屏、音效和在线部署属于后续阶段。

## 操作

```powershell
git checkout main
git pull origin main
docker compose up -d --build
```

打开球馆首页：上传比赛，选择“CPU 视觉候选（免费）”或“声音峰值候选”。Worker 完成后人工打开视频核对候选，调整开始/结束时间、通过或剔除，也可手动新建精彩片段。只有人工通过的片段才会进入 MP4。

在“生成高光视频”选择全场或某个球员，点击加入渲染队列。重复点相同请求不会复制任务。下方列表可以刷新状态、查看进度、下载剪辑清单 JSON、取消待渲染任务。出错时可查看报错并按原快照最多重试到第三次；如果人工审核已经变更，需要重新创建一条新的导出。

Worker 必须持续运行。若 Worker 被强制关闭或主机断电，运行中任务可能停留在 `running`，当前**不会自动抢占或重试这种不确定状态**；需要管理员核查源文件/进程，并手动恢复。并行多 Worker、资源配额、持久任务租约、商业稳定性运维均非 V1.0 已验收范围。

## 实际验证

- GitHub Django 回归覆盖快照一致性、重复提交、错球馆越权、取消/失败重试、撤销审核后失败及历史任务兼容；
- FFmpeg 本地/CI 实际合成视频编码回归；
- `.github/workflows/v10-real-human-review-smoke.yml` 使用 **真实 CC0 篮球传球视频**，实际执行 Django 上传、CPU 视觉建议、模拟测试审核、锁定快照、实际 FFmpeg MP4 渲染，并下载和验证编辑清单。
- **该集成烟雾测试的审核操作是自动化模拟，不是人类专家真正审核进球**；因此不能报告投篮识别准确率，不等于模型通过 V0.9 数据门禁。

请先在私有环境进行完整赛事的人工操作验收，收集适当的录像及肖像使用授权，再对外收费提供人工审核辅助剪辑。AI 全自动商业发布须有独立、真实、足够样本的盲测。
