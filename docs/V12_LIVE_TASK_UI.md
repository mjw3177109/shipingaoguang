# BasketCut V1.2 · 实时任务状态与上传体验

## 新增交互

### 1. 任务状态自动刷新

比赛详情页和篮球逐帧标注页调用登录保护的 `GET /games/<id>/tasks/status.json`。接口使用球馆 owner 范围检查，并返回当前分析状态、分析错误、Worker 自动恢复次数、抽帧状态、抽帧错误、候选帧数量，以及服务器渲染的最新导出表格局部 HTML。

- 活跃任务存在时每 5 秒轮询；
- 仅替换状态文字、错误提示、抽帧计数和导出记录，不重载整页、不重置视频播放；
- 所有任务完成后停止自动轮询；用户可以手动点“立即刷新任务状态”；
- 401/403/404 会停止轮询；暂时的网络/服务器错误会稍后重试；
- 响应带 `private, no-store`，并再次检查登录账号与球馆归属。

### 2. 上传进度

比赛上传表单用 XMLHttpRequest 的上传进度事件显示百分比。100% 只代表浏览器已把文件传输完毕，不代表后端已经完成视频探测。页面会继续显示“服务器正在校验视频”，收到 Django 的最终跳转响应后再进入比赛详情页。

网络中断时，界面明确提示先检查比赛列表，以免在服务端已经收到完整文件的情况下误操作重复上传。若 JavaScript 不可用，原始 HTML 表单仍可正常提交。

### 3. CSRF

Django 模板配置补充 `django.template.context_processors.csrf`，确保普通表单与通过状态接口重新渲染的取消/重试表单都有有效 token。任务状态接口仍只返回本账号有权访问的比赛。

## 验收与限制

- Django 测试覆盖状态接口鉴权、私有缓存头、排队/完成状态、导出操作片段、上传进度入口与视频 DOM 保留。
- 浏览器自动轮询不等于已经完成真人端到端验收；部署后仍应在 Chrome 中验证大文件上传、断网恢复、Worker 重启和手机布局。
- 4GB 上传上限还受浏览器、Gunicorn、反向代理、容器磁盘及网络超时限制。若部署在公网，需将代理 body size 与读写超时配置同步到 `MAX_UPLOAD_BYTES`；不要仅凭进度条完成就断定后端文件已成功校验。
- V1.2 不更改 CPU 视觉启发式的准确性声明；所有自动候选仍需人工审核。
